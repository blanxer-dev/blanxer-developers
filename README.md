# developers.blanxer.com

Source of https://developers.blanxer.com. Repository: https://github.com/blanxer-dev/blanxer-developers (MIT, see `LICENSE`).

Two things on one site:

- **`/`**: the BlanxerAPI landing page. "Your AI agent builds the store. Blanxer powers it." It carries the copy-paste prompt for Claude Code, Codex, Cursor and other agents.
- **`/api-docs/`**: the developer docs, which the agent reads to build the site. It contains guides for a custom Next.js website for a Blanxer store, `llms.txt` for agents, and an OpenAPI spec for the public endpoints a site uses.

Next.js 16 (App Router, static export) + Tailwind 4, in the look of enterprise.blanxer.com. Hosted on Cloudflare Pages.

## Layout

```
content/*.md            the guides: the only copy (index.md = the docs overview)
content/guides.json     sidebar groups and order (also prev/next and llms-full.txt order)
public/llms.txt         the agent index (llms.txt convention), hand-written
public/openapi.yaml     OpenAPI 3.1, only the endpoints a custom site uses
public/art/             graphics (GPT Image 2.5, glass style of enterprise.blanxer.com)
public/og.jpg           social card
public/_headers         Cloudflare Pages headers (content types, CORS for agents)
public/_redirects       old paths (/checkout.md, /quickstart …) -> /api-docs/…
scripts/content.mjs     copies content/*.md to public/api-docs/, writes llms-full.txt, checks links
src/app/page.tsx        the landing page
src/app/api-docs/       the docs (layout = sidebar + search; [slug] = one guide)
src/lib/docs.ts         Markdown -> HTML (marked + shiki), headings, table of contents
src/lib/site.ts         copy, the prompt, FAQ, links
```

`public/api-docs/` and `public/llms-full.txt` are generated (git-ignored).

## Build

```bash
npm install
node scripts/content.mjs && ./node_modules/.bin/next build     # -> out/
```

On Blanxer machines, call the binaries directly instead of `npm run build`. A stray `~/node_modules` can make `npm run` pick the wrong Node.

`scripts/content.mjs` **fails** in three cases:
- a guide links to a page that doesn't exist;
- `llms.txt` links to a file that isn't built;
- a file in `content/` isn't listed in `content/guides.json`.

Guides link to each other as `https://developers.blanxer.com/api-docs/<slug>.md`, which is what agents need when they read the raw files. The HTML pages rewrite those links to `/api-docs/<slug>/`.

Preview locally: `cd out && python3 -m http.server 3070`. Every page is written as `<path>/index.html` (`trailingSlash`), so any static server works.

## URLs

| URL | What |
|---|---|
| `/` | landing page |
| `/api-docs/` | docs overview (`content/index.md`) |
| `/api-docs/<slug>/` | a guide, as HTML |
| `/api-docs/<slug>.md` | the same guide, raw (what agents fetch) |
| `/llms.txt`, `/llms-full.txt`, `/openapi.yaml` | agent files |
| `/sitemap.xml`, `/robots.txt` | generated by Next |

Each docs page has **Copy page** (Markdown), View as Markdown, Open in Claude, Open in ChatGPT and Copy link to llms.txt. ⌘K searches titles and headings, and code blocks have a Copy button.

## Adding or renaming a guide

1. Add `content/<slug>.md`, starting with a `# Title`.
2. Add it to `content/guides.json`, which sets its group, sidebar label and order.
3. Add a line to `public/llms.txt`.
4. Run the build. If you renamed a page, add the old path to `public/_redirects`.

## Cloudflare Pages settings

| Setting | Value |
|---|---|
| Framework preset | None |
| Build command | `npm install && node scripts/content.mjs && npx next build` |
| Build output directory | `out` |
| Root directory | `/` |
| Environment variable | `NODE_VERSION` = `20` (or newer) |
| Custom domain | `developers.blanxer.com` |

## Keeping it true

Every fact in the guides comes from code:
- the backend (`gigbig_backend`, branch `dev`, plus `feat/storefront-url`);
- the Blanxer storefront (`blanxer-storefront-web` `main` at `cabd695`).

When the checkout, an endpoint or a limit changes there, change the guide and `openapi.yaml` in the same week. The package page (`content/package.md`) describes the contract surface and defers to the package README for the released API.

The landing page's prompt (`buildPrompt` in `src/lib/site.ts`) must stay word for word the same as the dashboard's BlanxerAPI page.

Validate the spec after edits:

```bash
npx @redocly/cli lint public/openapi.yaml
```
